# Replit build prompt — Dairy Management Platform (MVP)

Copy everything below into Replit's AI Agent chat to start the build.

---

Build a full-stack dairy supply chain management web app called "DairyTrack" (MVP version). This will eventually scale to 600 villages/farms, 600 milk collection centers, 100 processing plants, and 600 supermarkets — so structure the data model to support that scale from day one, even though the initial build only needs sample/demo data.

## Tech stack
- Frontend: React (Vite) + Tailwind CSS
- Backend: Node.js + Express
- Database: PostgreSQL (use Replit's built-in PostgreSQL database)
- Auth: Simple email/password auth with role-based access control (JWT sessions)

## User roles (role-based dashboards, same login system)
1. **Admin** — sees everything across all villages, farms, plants, supermarkets
2. **Farmer** — sees only their own farm, cows, health records, and milk deliveries
3. **Collection center staff (ARC)** — sees farms feeding into their center and daily milk intake
4. **Processing plant staff** — sees incoming batches and product output
5. **Supermarket staff** — sees their stock levels and orders

## Database schema (build these tables with proper foreign keys)
- `villages` (id, name, district, state)
- `farms` (id, village_id FK, farmer_name, phone, address)
- `cows` (id, farm_id FK, tag_id, breed, date_of_birth, lactation_status)
- `health_records` (id, cow_id FK, visit_date, diagnosis, vet_name, notes, next_checkup_date)
- `collection_centers` (id, village_id FK, name, location)
- `milk_collections` (id, farm_id FK, collection_center_id FK, collected_on, quantity_liters, fat_percent, snf_percent)
- `processing_plants` (id, name, location)
- `batches` (id, plant_id FK, collection_center_id FK, processed_on, total_liters)
- `products` (id, batch_id FK, sku, product_type, quantity, manufacture_date, expiry_date)
- `supermarkets` (id, name, location)
- `orders` (id, supermarket_id FK, product_id FK, quantity, order_date, status)
- `users` (id, name, email, password_hash, role, linked_entity_id — links a user to their farm/center/plant/supermarket)

## Pages/features to build

**Auth**
- Login page with role-based redirect after login
- Simple signup for admin to create farmer/staff accounts

**Admin dashboard**
- Summary cards: total villages, farms, cows, active health alerts, total milk collected today, total orders pending
- Table views for villages, farms, plants, supermarkets with search/filter
- A simple chart showing milk collection volume over the last 7 days

**Farmer view**
- List of their own cows with tag ID, breed, and health status
- Add/edit cow profile
- Add a health record for a cow (date, diagnosis, vet name)
- Log daily milk delivery (quantity, fat %, date)
- See their delivery history in a simple table

**Collection center (ARC) view**
- Table of milk collections received today from all linked farms
- Ability to mark a batch as "sent to processing plant"

**Processing plant view**
- List of incoming batches with source collection center and volume
- Form to log a new product output linked to a batch (SKU, type, quantity, expiry)

**Supermarket view**
- List of available products they can order
- Place an order (product, quantity)
- View order history and status

## Design
- Clean, simple, mobile-friendly UI (many users will be on phones with basic literacy — use clear icons alongside text labels)
- Use a calm color palette (greens/blues, dairy-appropriate)
- Keep forms short and avoid dense tables where possible — card-based layouts for mobile users

## Build order (please build in this sequence and confirm each step works before moving to the next)
1. Set up database schema and seed with sample data (3 villages, 5 farms, 15 cows, 2 collection centers, 1 processing plant, 3 supermarkets)
2. Build auth system with role-based login
3. Build farmer view (cow management + milk delivery logging)
4. Build collection center view
5. Build processing plant view
6. Build supermarket view
7. Build admin dashboard last, since it aggregates data from everything else
